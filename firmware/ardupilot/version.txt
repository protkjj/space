# ArduPilot version pinning
# See README.md for provenance and the validation record.
#
# SITL and hardware are pinned separately on purpose. ArduPilot documents
# Simulation-on-Hardware as still changing, so a SITL pin must not be assumed
# to apply to a hardware or HILS build.

[SITL]
tag: Rover-4.7.0
commit: 1511f27194f1dcc3728270883047bdf022b3fd53
status: selected to match the firmware flashed on the target board
validated: command path only
# Re-pinned from Rover-4.6.3 once the Pixhawk 6X was found to be running
# 4.7.0, then re-measured on this revision rather than carrying the 4.6.3
# results over. See README.md for what was and was not confirmed.
#
# Confirmed here: DDS interface present, mode switch to GUIDED, arming,
# ArduPilot-authoritative motion, disarming.
# Not confirmed here: Gazebo plugin, TF and odometry ownership, sensor
# streams, stop latency as a specified limit, GPS-denied operation.
#
# Toolchain note: ArduPilot 4.7 and later require the v4.7.0 branch of
# Micro-XRCE-DDS-Gen. The v4.5.1 branch is for pre-4.7 only, and mixing them
# fails during IDL generation rather than at configure time.

[Hardware]
tag: Rover-4.7.0
commit: 1511f27194f1dcc3728270883047bdf022b3fd53
status: built from the SITL pin with --enable-DDS and flashed to the board
validated: DDS interface only
# The board originally ran a stock 4.7.0 build with no AP_DDS, so it had no
# DDS_ENABLE parameter. A Pixhawk6X build was produced from the pinned commit
# and flashed. board_id 53 matched the bootloader's reported ID.
#
# Confirmed on the board after flashing: the XRCE agent attaches over the
# second USB CDC interface (SERIAL8/OTG2, protocol 45) and the same 18 /ap/*
# topics as SITL appear in the ROS graph, with the adapter publishing to
# /ap/cmd_vel and AP_DDS subscribing.
#
# Not confirmed: arming, any motion, and any drivetrain behaviour. Arming is
# blocked by first-time vehicle commissioning, not by this build. See
# README.md for the exact pre-arm messages the board reported.
